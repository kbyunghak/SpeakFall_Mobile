# SpeakFall 낙하 구조 모드 — UI/UX 개선 계획

업로드하신 검토 문서(종합 7.5/10)의 지적사항을 우선순위대로 반영하기 위한 계획입니다.

## 1. 핵심 방향

현재 화면은 콘셉트와 감성은 잘 잡혔지만 **상태 구분**과 **행동 유도**가 약합니다.
"지금 무엇을, 언제 말해야 하는가"를 화면이 스스로 말해주도록 바꾸는 것이 이번 작업의 목표입니다.

## 2. 게임 상태 흐름 재설계 (P0)

```text
대기 → 마이크 권한 → 카운트다운(3·2·1) → 플레이 → 결과 → 라운드 종료
```

- 대기: 캐릭터가 지면 위에서 대기, "목소리로 친구를 구해보세요" 안내
- 권한: "마이크 켜고 시작" 단일 CTA. 거부 시 브라우저 설정 안내 표시
- 카운트다운: 권한 승인 후에만 진행, 이 시점까지 낙하 없음
- 플레이: 채점 대상은 **항상 1개**. 다음 단어는 상단 미리보기로만 노출
- 결과: 정답이면 낙하산 전개, 시간 초과면 착지 + 하트 1 감소

현재는 권한이 없어도 낙하가 시작되고 "MIC OFF"와 플레이가 동시에 보이는 문제를 이 흐름이 해소합니다.

## 3. 화면 요소 정리 (P0)

- 상단 HUD: 점수 / 구조 인원 / 하트만 유지, 나머지 제거
- 활성 단어 카드: 단어를 가장 크게, 발음기호는 보조. 의미 미정인 별 아이콘은 제거
- 활성 캐릭터만 중앙 안전 영역에 배치 — 화면 가장자리 잘림 제거
- "말해보세요: garden" 형태의 명시적 행동 유도 문구를 첫 플레이에 노출
- 성공/실패 데모 버튼은 개발 빌드에서만 표시

## 4. 피드백 규칙 (P1)

| 상태 | 피드백 | 문구 |
| --- | --- | --- |
| 정답 | 낙하산 전개, 안전 착지 | 좋아요! |
| 오인식 | 카드 흔들림 + 낙하 속도 0.5~1초 완화 | 한 번 더 말해보세요 |
| 시간 초과 | 착지 + 하트 1 감소 (과장 없음) | 괜찮아요, 다음 친구를 구해요 |
| 연속 정답 | 콤보 숫자 + 특별 낙하산 | 3 COMBO! |

오인식은 즉시 감점하지 않고 최소 1회 재시도를 보장합니다.

## 5. 연출 강화 (P1)

- 마이크 감지 시 150ms 이내 파동 애니메이션 시작
- 낙하감: 캐릭터 흔들림, 속도선, 구름 이동
- 지면 근접 시 경고 색상 전환

## 6. 이후 단계 (P2)

- 캐릭터·낙하산 수집 도감
- 발음기호 숨기기 옵션 (초보자용)
- 별 아이콘을 보상 재화로 재정의할지 결정

## 7. 작업 순서

1. 게임 상태 머신 분리 (대기/권한/카운트다운/플레이/결과/종료)
2. 활성 단어 1개 채점 구조로 전환 + 다음 단어 미리보기
3. 성공·실패 결과 애니메이션 분기
4. 마이크 파동, 재시도 완화, 근접 경고
5. 점수·콤보·구조 인원·하트 규칙 연결
6. 데모 버튼을 개발 빌드 전용으로 격리

## 8. 기술 메모

- 상태 머신은 `SpeakFallGame.tsx` 내부의 `phase` 상태(`idle | permission | countdown | playing | result | summary`)로 관리
- 낙하 대상 배열을 단일 활성 객체 + 대기열로 분리
- 데모 버튼은 `import.meta.env.DEV` 조건부 렌더링
- 마이크 권한은 `navigator.permissions` 조회 후 `useSpeechRecognition` 시작
