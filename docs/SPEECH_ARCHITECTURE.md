# SpeakFall 음성 인식 구조

## 목적

SpeakFall의 음성 기능을 빠른 게임 반응과 정확한 발음 피드백으로 분리해 확장합니다. 현재 Android와 웹의 기본 음성 인식은 그대로 유지하고, 향후 필요한 경우에만 Whisper 또는 발음 평가 서비스를 연결합니다.

## 현재 동작

1. 사용자가 게임 또는 받아쓰기 화면에서 마이크를 시작합니다.
2. Android 앱은 `@capacitor-community/speech-recognition`, 웹은 Web Speech API를 사용합니다.
3. 인식 엔진이 가장 가능성 높은 문장과 대체 후보를 반환합니다.
4. 모든 결과는 공통 `SpeechResult` 형식으로 변환됩니다.
5. 게임의 발음 판정기는 목표 단어와 후보들을 비교하고 난이도 및 트랙 보정값을 적용합니다.
6. 통과하면 구조 성공, 실패하면 인식된 표현과 재시도 피드백을 표시합니다.

```text
마이크 입력
  ├─ Android SpeechRecognizer
  └─ Web Speech API
          ↓
      SpeechResult
          ↓
  PronunciationEvaluator
          ↓
   게임 결과 및 피드백
```

## 공통 결과 형식

`src/lib/speech/types.ts`의 `SpeechResult`는 다음 정보를 담습니다.

| 필드            | 설명                                                        |
| --------------- | ----------------------------------------------------------- |
| `transcript`    | 가장 가능성이 높은 인식 문자열                              |
| `alternatives`  | 엔진이 제공한 대체 후보와 선택적 신뢰도                     |
| `confidence`    | 엔진 신뢰도. 제공할 때만 존재                               |
| `pronunciation` | 전문 발음 평가 엔진을 연결할 때만 존재하는 점수와 음소 결과 |
| `isFinal`       | 최종 인식 결과 여부                                         |
| `engine`        | 결과를 생성한 음성 엔진                                     |
| `timestamp`     | 결과가 생성된 시각                                          |

현재 기본 엔진은 음소 점수나 일관된 신뢰도를 항상 제공하지 않으므로 값이 없는 선택 필드는 만들지 않습니다.

## 단계별 업그레이드 계획

### 1단계: 구조 분리 — 적용됨

- Android와 웹 결과를 `SpeechResult`로 통일
- 음성 인식과 게임 판정을 분리
- 받아쓰기 테스트 화면에 실제 사용 엔진 표시
- 기존 게임 난이도와 점수 기준 유지

### 2단계: 선택적 Whisper 재인식

기본 엔진 결과가 없거나 신뢰도가 낮고, 특히 어려움 모드의 최소대립쌍 문제일 때만 녹음한 짧은 오디오를 Whisper 백엔드로 보냅니다. 모든 발화를 전송하지 않아 반응 지연과 비용을 줄입니다.

권장 조건 예시:

- 기본 엔진이 결과를 반환하지 않음
- 여러 후보가 목표 단어 주변에서 충돌함
- 어려움 모드에서 `/r/–/l/`, `/f/–/p/`, `/v/–/b/`, `/θ/–/s/`, `/ɪ/–/iː/`, `/æ/–/ɛ/`를 평가함

API 키는 앱에 포함하지 않고 서버 또는 서버리스 함수에 보관해야 합니다. 사용자의 음성을 외부 서비스로 보내기 전에 개인정보 처리방침, 동의 문구, 보관 정책도 함께 갱신합니다.

### 3단계: 음소 단위 발음 평가

Whisper 전사는 “무슨 단어로 들렸는지” 확인하는 데 적합하지만 정확히 어떤 음소가 틀렸는지를 직접 보장하지 않습니다. 구체적인 발음 교정에는 Azure Pronunciation Assessment 같은 발음 평가 엔진을 별도 어댑터로 연결합니다.

반환된 음소 점수는 `SpeechResult.pronunciation`에 저장하고, 게임 화면에는 다음처럼 표시할 수 있습니다.

```text
목표: ship /ʃɪp/
인식: sheep /ʃiːp/
피드백: /ɪ/가 /iː/에 가깝게 들렸어요.
```

## 판정 원칙

- 쉬움: 상위 5개 후보에서 정확한 단어를 먼저 찾고, 없으면 문자열 유사도를 허용합니다. 실제 최소대립쌍 충돌은 통과시키지 않습니다.
- 보통: 상위 5개 후보 안에 정확한 단어가 있어야 통과합니다. 문자열 유사도는 사용하지 않습니다.
- 어려움: 첫 번째 후보가 정확히 일치해야 통과합니다.
- 엔진의 신뢰도는 보조 정보이며, 단독으로 정답을 결정하지 않습니다.
- 발음기호 피드백은 실제 음소 평가 결과가 있을 때만 “틀린 음소”로 확정합니다.

## 테스트 체크리스트

- 웹과 Android에서 엔진명이 올바르게 표시되는가
- 한 단어 성공·실패 뒤에도 다음 인식이 자동으로 이어지는가
- 대체 후보 중 정답이 있으면 현재 난이도 규칙에 따라 통과하는가
- 새 게임에서 남은 단어와 음성 세션이 초기화되는가
- 쉬움·보통의 기존 인식 허용 범위가 바뀌지 않았는가
- 어려움 모드의 최소대립쌍이 잘못 자동 통과되지 않는가
- 네트워크 또는 외부 평가 서비스 실패 시 기본 엔진으로 계속 플레이할 수 있는가

### Android 실제 기기 생명주기

- 게임 시작 후 첫 발음이 정상적으로 인식되는가
- 10회 연속 발음 후에도 마이크가 계속 동작하는가
- 틀린 발음 뒤에 음성 세션이 자동으로 재시작되는가
- 발음 듣기에서 마이크 정지 → TTS 재생 → 마이크 재시작이 순서대로 동작하는가
- 게임 → 받아쓰기 → 게임 화면 이동 후 중복 세션이 생기지 않는가
- 앱을 백그라운드로 보낸 뒤 돌아왔을 때 인식이 복구되는가
- 마이크 권한을 거부한 뒤 재시도할 수 있는가
- 빠른 연속 발음이 이전 단어 결과로 잘못 처리되지 않는가
- 무음 상태 후에도 다음 발음을 받을 수 있는가
- Android STT 오류 후 자동 또는 사용자 재시도로 복구되는가

## 관련 파일

- `src/hooks/useSpeechRecognition.ts`: 현재 Android/Web 인식 어댑터
- `src/lib/speech/types.ts`: 공통 음성 결과 및 엔진 계약
- `src/lib/speech/pronunciationEvaluator.ts`: 게임 발음 판정
- `src/components/speakfall/SpeakFallGame.tsx`: 게임 연결
- `src/routes/dictation.tsx`: 받아쓰기 및 인식 확인 화면
